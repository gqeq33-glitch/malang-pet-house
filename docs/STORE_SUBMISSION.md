## 3. 대상 연령과 등급 (답변 초안)

- 대상: 만 5~12세와 보호자. 어린이 대상 앱으로 선언.
- 폭력·성적 내용·도박·약물: 없음. 사용자 간 소통: 온라인 없음. 친구 코드는 앱 밖에서 직접 전달하며, 펫 이름(8자)이 포함됨을 심사 답변에 명시.
- 위치 공유, 광고, 외부 링크: 없음. 앱 안의 개인정보처리방침 링크 추가 여부는 제출 전 점검.

## 4. Google Play Data safety (답변 초안)

| 질문 | 답변 |
|---|---|

**결제를 넣으면 답이 바뀝니다.** 구매 기록과 외부 결제 도구 사용 내역을 다시 작성해야 합니다.

## 5. Apple App Privacy (답변 초안)

"Data Not Collected"로 답할 수 있는지 제출 전 확인합니다. 키즈 카테고리에 낸다면 제3자 분석과 광고 금지, 외부 링크와 구매 전 보호자 확인 등의 추가 기준을 점검합니다. 곱셈 문제가 Apple의 parental gate 기준을 충족하는지도 심사 전에 확인합니다.

## 6. 심사 안내 자료 초안

- **로그인:** 없음. 계정이 필요 없습니다.
- **시작:** 이름 입력 → 알을 세 번 누르기 → 나이 선택 → 첫 영어 레슨.
- **보호자 메뉴:** 오른쪽 위 ⚙️ → 보호자 메뉴 → 곱셈 문제 또는 PIN.
- **온라인 기능:** 없음. 앱은 게임 시작 후 인터넷을 쓰지 않습니다.
- **친구 코드:** 사용자가 복사해 앱 밖에서 전달하는 글자이고, 쪽지는 정해진 12개 중 번호만 전달합니다.
- **음성:** 기기 TTS 사용. 마이크와 녹음 없음.

## 7. 수익화 설계 (미구현)

**이번에 결제 코드를 넣지 않았습니다.** 개발자 계정, 스토어 상품 등록, 정산 정보가 없으면 동작하지 않고, 시험할 수 없는 결제 화면을 어린이 앱에 넣는 것은 위험하기 때문입니다. 준비되면 아래 구조로 구현합니다.

### 무엇을 팔 것인가

| 구분 | 내용 |
|---|---|
| 무료 | 지금의 전체 게임과 기초 영어 과정. 이미 제공한 내용은 잠그지 않음 |
| 프리미엄(보호자) | 추가 회화 과정, 상세 학습 보고서, 원어민 녹음 음성(제작 시) |
| 콘텐츠 팩 | 파닉스 심화, 학교 영어, 여행 영어 등 |
| 하지 않을 것 | 코인·뽑기·확률형 아이템 판매, 아이 화면의 구매 유도, 시간제한 할인 압박 |

### 가격 실험 (가설)

| 안 | 가격 | 측정 |
|---|---|---|
| A | 월 3,900원 | 구매 전환율, 1개월 해지율 |
| B | 연 29,900원 | 연간 선택 비율 |
| C | 팩 4,900~9,900원 | 팩별 구매율 |

사용자 시험의 구매 의향은 실제 구매와 다르므로, 소규모 출시 후 **실제 전환율로만** 조정합니다.

### 결제 구조

- **보호자 전용 구매 영역:** 보호자 메뉴(PIN 또는 확인) 안에만 둡니다. 어린이 화면에는 가격과 구매 버튼을 두지 않습니다.
- **스토어 결제:** 앱 안 디지털 상품은 Google Play Billing과 Apple In-App Purchase를 사용합니다. Capacitor용 결제 플러그인이나 RevenueCat 같은 서비스 도입 시 Data safety를 다시 씁니다.
- **구독 복원:** 보호자 메뉴에 "구매 복원" 버튼을 둡니다. 저장 데이터나 백업 코드가 아니라 스토어 영수증을 기준으로 합니다.
- **구매 상태 검증:** 기기 저장값만 믿으면 쉽게 위조되므로, 스토어 영수증 검증 서버나 검증 서비스가 필요합니다. 운영비가 생깁니다.
- **구독 취소 안내:** 각 스토어의 구독 관리 화면으로 연결하고 취소 방법을 적습니다.
- **결제 오류:** 취소, 실패, 대기, 네트워크 오류를 구분해서 보호자에게 안내하고, 실패 시 권한을 주지 않습니다.
- **환불·지원:** 환불은 각 스토어 절차로 안내하고, 지원 이메일 답변 기준을 정합니다.
- **문서 수정:** 결제를 넣을 때 개인정보처리방침, Data safety, App Privacy, 소개 문구를 함께 고칩니다.

## 9. 운영자가 직접 해야 할 일 (순서대로)

1. 지원 이메일을 정하고 `www/privacy.html`의 `YOUR-EMAIL@example.com` 2곳을 교체
2. 육아휴직 중 수익 활동이 급여에 영향을 주는지 고용센터(1350)에 먼저 확인
3. 패키지 ID와 앱 이름 확정, 상표 검색
4. Google Play·Apple 개발자 계정 가입, 서명 키 생성
5. 실제 기기 시험 후 사용자 시험 진행
6. 영어 교사 또는 원어민 검수 (`docs/content_review.csv`)
7. 규격 스크린샷 제작 후 내부 테스트 트랙으로 제출
8. 결제 도입 여부를 사용자 시험 결과로 결정
